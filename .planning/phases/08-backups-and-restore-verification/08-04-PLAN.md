<objective>
Close gap G-08-6: make the /internal/operations center reachable by a human operator through the documented ingress chain (operator gateway → signed web proxy → OperatorGuard). Today an AND-gate blocks every browser user: (1) the gateway's protected-path allowlist signs only replay paths, and (2) the gateway is not part of the documented dev topology, so no HMAC signing source exists for a human at all.

Purpose: UAT test 6 reported «все недоступно» — the backup/restore operations center and its two manual trigger buttons are unreachable for the operator even though the underlying backup functions work (UAT test 1 passed through a signed in-process driver). This plan makes the requirement from 08-03-PLAN («operator through the gateway → signed web proxy → OperatorGuard») actually achievable.

Output: gateway signs operations paths under the same OPERATOR_PROXY_SIGNING_SECRET; the dev launcher runs the gateway; an e2e test proves a real browser with Basic auth sees the blocks and presses both trigger buttons.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → gateway :8080 | Untrusted human client; Basic auth is the only credential it holds |
| gateway → web :3000 | Gateway attaches HMAC operator headers; the web proxy re-verifies them |
| .env → gateway process | Signing secret and Basic credentials enter via Load-Env only, never argv or logs |

| T-08-18 | Spoofing | infra/operator-gateway/security.mjs | high | mitigate | Operations prefixes join the same Basic-auth + HMAC machinery as replay: authenticateBasic (constant-time pair compare) gates the request, signedOperatorHeaders binds subject/timestamp/method/pathname/query-digest, and server.mjs strips any client-supplied x-operator-* headers before signing — a browser can never forge an operator identity.
