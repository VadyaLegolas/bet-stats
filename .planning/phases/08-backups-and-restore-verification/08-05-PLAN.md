<objective>
Close gap G-08-5: the drill's container-cleanup verdict is derived solely from the exit code of `docker rm --force` (backup-drill.ts:438-439). On Docker server 29.x `rm -f` is idempotent (exit 0 for a non-existent name), so identity loss before cleanup — the live rename race observed in UAT — is masked as an honest `REMOVED` while an orphan container stays alive.

Purpose: the phase's T-08-10/D-11 contract is that cleanup failure is recorded, not hidden. Today the recording channel itself can lie. This plan replaces the exit-code guess with object verification: inspect before rm (catches rename/loss), rm, inspect after rm (catches "rm said 0 but the container survived"), and records the container name plus verdict evidence in the receipt's checks JSON for audit.

Output: an inspect-verified containerCleanup verdict in runBackupDrill, full unit coverage of the FAILED branch (including overall-not-recolor), and a real-docker integration assertion.
</objective>
