Rationale: the "configurable" webhook endpoint (ALRT-04) remains a delivery-channel configuration exactly as CONTEXT.md D-01 scoped it — a single optional `ALERT_WEBHOOK_URL` receiving a generic JSON POST, with SMTP explicitly deferred and the channel modeled as a dispatcher attempt over durable PostgreSQL state (D-02). </assumption_delta_decision>

<objective>
Close the two critical verification gaps in the alerting composition loop: CR-01 (the BullMQ dead-letter inspector is created in `startAlertingRuntime` but never passed to `scheduleAlertingTick`, so the DEAD_LETTER signal — including CRITICAL for blocking root causes per D-03 — never fires in production) and CR-02 (`resolveClearedAlerts` unconditionally auto-resolves the `DELIVERY_HEALTH\0synthetic` probe anchor within one tick, killing the D-13 CRITICAL self-alert while the channel is still broken). Also close IN-05, which becomes mandatory once CR-02 removes the evaluator as an anchor-resolution path: a successful probe must resolve the anchor from ACKNOWLEDGED as well as OPEN.

Purpose: Without these fixes the phase goal is not achieved — the operator is never told about dead letters (5 of 6 adapters effectively live) and the alerting system gags its own most important self-alert. Both defects sit at the module-composition seam that unit tests on fakes could not see, so every fix ships with a cross-module composition test.
Output: Patched `main.ts` / `alerts.ts` / `delivery-probe.ts`, new composition test file, extended probe test file; all existing alert behavior preserved.
</objective>
