# Phase 14 — UI Design Contract

> Visual and interaction contract for Phase 14 (Asian Handicap and Exact Score Markets). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Decisions D-04, D-05..D-10, D-19, D-20, D-21 of `14-CONTEXT.md` are binding. The user delegated every discretionary decision to Claude («реши сам»); each such decision is recorded below with its rationale (see "Source Decisions Applied"). All user-facing text is Russian (AGENTS.md convention); identifiers, CSS classes and commit messages stay English. This spec is written in English like every other planning artifact; every string in a "Copy" cell is the exact Russian text to ship.

**Scope.** Two new match-page sections («Азиатский гандикап», «Точный счёт»); the unavailable/legacy state (`SCORE_MATRIX_UNAVAILABLE`); odds-form additions (AH line selection, 17-selection exact-score book); the value outcome card with push-aware EV breakdown and the push/half-win explanation sentence; the scorecard candidate registry labels for the new markets; Russian label additions in `enum-labels.ts`; the `/methodology` section and model-card copy. **Out of scope:** closing-odds browser form (stays API/CLI, Phase 13), probabilistic scoring and calibration of the new markets, Asian totals, charts of any kind (Recharts stays absent, Phase 10 D-09).

### Visual Direction

- Same calm analytical workbench as the rest of the match page: hairline borders, `.panel`/`.workbench-card` surfaces, no sportsbook cues (no odds tickers, no heatmap gradients, no red/green win-loss framing, no urgency treatments).
- The five AH outcomes and the 17 exact-score cells are **numbers in a table**, never colour-coded. No bars, no heatmap shading. The only emphasis in the whole phase is the main-line row (accent wash + rail + a text chip).
- Layout reuses the existing 1200px frame; the two new sections are full-width `panel workbench-card` siblings, not nested inside another panel.

## Typography

New surfaces use exactly four sizes and two weights. (Inherited components such as `.facts-grid dt` at 13px or the 12px `.state-chip` are not used by the new markup; use `state-chip state-chip--md` for 14px chips.)

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / meta / table header / legend / chip / sub-line | 14px | 400 (headers and chips 600) | 1.4 |
| Body / table cells / controls / notices | 16px | 400 (emphasis 600) | 1.55 (inherited body) |
| Sub-heading (`h4` in the value breakdown) and summary value | 20px | 600 | 1.2 |
| Section heading (`h3` of each new section, inherited `.workbench-card > h3`) | 24px | 600 | 1.18 (inherited heading) |

Rules:

- Weights are 400 and 600 only on new surfaces. Never communicate state through weight alone — the main-line row, unavailable fair odds and structural zeros always carry visible text.
- All numeric columns, grid cells and summary values use `font-variant-numeric: tabular-nums`.
- Probabilities: `percent()` → one decimal («38.1%»). Fair and quoted odds: `formatOdds()` → two decimals («1.93»; values ≥1000 render as «1234.57», no thousands separator). Signed returns and contributions use U+2212 for negatives («−0.500»), `+` for positives, bare «0.000» for zero. Line labels use U+2212 for negative lines («−0.75») and an ASCII `+` («+0.25»); the level line is «0». The canonical ASCII token (`-0.75`) is for ids and storage only and is never shown.
- Numbers never truncate or ellipsize. Long strings (snapshot ids, source labels inside `<option>`) follow the existing `overflow-wrap: anywhere` rules.

## Layout and Placement

Inside `ForecastWorkbench` (h2 «Прогнозы и ручной поиск value»), in this order:

1. existing header, revision comparison, «Замороженный прогноз» panel (unchanged);
2. **new** `<section id="asian-handicap" aria-labelledby="asian-handicap-heading" class="panel workbench-card">` with `h3` «Азиатский гандикап»;
3. **new** `<section id="exact-score" aria-labelledby="exact-score-heading" class="panel workbench-card">` with `h3` «Точный счёт»;
4. existing `.workbench-duo` (odds form + exact-snapshot comparison), then the value outcome section.

Heading hierarchy stays `h1 → h2 → h3 → h4` (D-19 "below the existing markets"; siblings of the forecast panel, not nested, so each is a landmark region and deep-linkable via `#asian-handicap` / `#exact-score`). Both sections follow the **currently selected forecast snapshot** (`forecast.id`); switching the «Снимок прогноза» select swaps both sections synchronously with no fetch (see data delivery).

**Data delivery (decision, UI-relevant).** Recommended: `page.tsx` (server component) fetches the extended-markets view for every listed forecast (`Promise.all`, same eligibility headers as `loadForecasts`) and passes `extendedMarkets: Record<forecastId, ExtendedMarketsView | { state: "READ_FAILED" }>` to the workbench. Rationale: the sections are visible on initial render, so a client-side fetch would add a loading state and layout shift to the audited load (CLS gate 0.09, Phase 10) and violate "fallbacks never mount during the gated initial load". Payload is a few KB per forecast. If the planner chooses a client fetch instead, the contract is: no skeleton, text-only `<p role="status">Загрузка: расширенные рынки…</p>` via `LocalDataBlock`, and the section keeps its heading mounted. The two sections are **eager** (not `next/dynamic`); only the tiny client component for the side toggle and expander ships.

**UI arithmetic prohibition.** The UI performs no probability arithmetic. `ah-settlement-v1` is one pure domain function shared by display and settlement (D-06). The DTO must therefore carry, per line: the home line token, the away line token, the five-way breakdown for **both** sides, the effective win probability, fair odds (or a typed unavailable reason) for both sides, and a `mainLine` token (D-08 selection is computed in the domain). The UI only formats, orders, windows and labels. Quarter-line "split between" notes come from a shared domain helper (adjacent whole/half lines), not from UI arithmetic.

### Asian handicap section anatomy

1. **Head row** (`.market-head`): `h3` «Азиатский гандикап»; chips `state-chip state-chip--md tone-neutral` «Без калибровки»; link «Как это считается» → `/methodology#extended-markets`.
2. **Deck** (`<p>`): «Вероятности исходов для линий от −2.5 до +2.5, рассчитанные по замороженной матрице счёта этого прогноза. Расчёт не использует коэффициенты букмекера.»
3. `ContextualMethodologyWarning context="extendedMarkets"` (copy below).
4. **Provenance line** (14px, muted): «Матрица счёта: {сохранена при выпуске прогноза | воспроизведена по сохранённым параметрам и сверена с рынками прогноза}. Правила: ah-lines-v1.» (`code` for the version id).
5. **Summary tiles** (`.market-summary`, 3 tiles, `<dl>`): «Главная линия» → «Хозяева −0.75 / Гости +0.75»; «Справедливый коэффициент на хозяев» → `1.93`; «Справедливый коэффициент на гостей» → `1.98` (each the main line's values; a tile whose fair odds are unavailable shows «Недоступно» + reason). One sentence under the tiles (14px): «Главная линия — та, на которой по модели шансы сторон ближе всего к равным.»
6. **Toolbar** (`.market-toolbar`): left — side toggle, `role="group" aria-label="Сторона гандикапа"` with two `button.filter-chip` («Хозяева», «Гости») using `aria-pressed`; default «Хозяева». Right — expander button (below).
7. **Table region** (`id="ah-lines"`), rendered through `ResponsiveEvidence` with `rowCurrent`:
   - desktop (≥768px): `<table>` with `<caption>`; columns in this order — «Линия» (row header, `th scope="row"`), «Выигрыш», «Выигрыш половины ставки», «Возврат ставки», «Проигрыш половины ставки», «Проигрыш», «Эффективная вероятность выигрыша», «Справедливый коэффициент». Wrapped by the existing `.evidence-table-scroll` labelled region (keeps the horizontal-scroll hint caption for 768–1024px).
   - mobile (<768px): one card per row (existing `.evidence-card`): `h4` = line label (+ chip on the main line); the accent `.evidence-denominator` line = «Эффективная вероятность выигрыша 52.3% · справедливый коэффициент 1.93»; the `warning` slot carries the quarter-line split note; five-way breakdown and fair-odds detail sit in the existing «Полные доказательства» `<details>` (open by default on the main-line card).
8. **Legend** (14px, directly under the table, always visible): «Прочерк — такого исхода на этой линии не бывает. Проценты округлены: сумма может отличаться от 100%.»
9. **How-to-read** `<details class="well">` with `<summary>` «Как читать таблицу» (copy below).

**Row identity and order.** A row's label is the displayed side's own line: «Хозяева −0.75» in home view; «Гости +0.75» in away view, with the home line as a 14px muted sub-line «(Хозяева −0.75)» in away view only. Rows are ordered ascending by the **displayed side's** line (away view therefore lists lines +2.5 … −2.5). Quarter lines add a 14px muted sub-line «ставка делится между −0.5 и −1» (adjacent lines from the shared helper, in the displayed side's sign convention); whole lines add no sub-line (the legend and how-to-read explain returns); the level line «0» adds «возврат при ничьей». Rows are always keyed by the home line token so toggling the side keeps the main-line row and the window stable.

**Main-line highlight (not colour-only).** The main-line row (desktop) / card (mobile) has `aria-current="true"`, a visible chip «Главная линия» inside the line cell (`state-chip state-chip--md tone-positive` with `state-dot`), the `--color-accent-soft` wash and a 4px accent inline-start rail on the first cell. In forced-colors mode the rail becomes `border-inline-start: 4px solid Highlight` and the chip border remains.

**Default view and expander (D-08).** Default = 5 consecutive rows in the displayed order, centred on the main-line row; when the main line is within two rows of an end, the window shifts so exactly 5 rows are always shown (e.g. main line −2.5 → rows −2.5 … −1.5). A visible 14px muted line above the table reads «Показаны 5 линий из 21 вокруг главной.» (expanded: «Показаны все 21 линия.»). The expander is a real `<button type="button" class="btn-secondary btn-compact">` with `aria-expanded`, `aria-controls="ah-lines"`; labels «Показать все 21 линию» / «Показать только 5 линий вокруг главной». Pressing it re-renders the rows prop of `ResponsiveEvidence` (all 21 in displayed order); focus stays on the button; a polite `role="status"` line announces «Показаны все 21 линия» / «Показаны 5 линий вокруг главной». The expanded state and chosen side are local component state, preserved when the selected forecast snapshot changes within the session, reset on reload; they are not URL state.

**Cell rules.**

- Structural zeros (HALF_WIN/HALF_LOSS on whole and half lines; PUSH on quarter and half lines) render «—» with `<span class="sr-only">такого исхода на этой линии не бывает</span>`; the visible legend explains the dash (no unexplained dash, Phase 1 rule). Real computed zeros render «0.0%».
- Fair odds unavailable: cell shows «Недоступно» with a 14px muted second line from `FAIR_ODDS_UNAVAILABLE_LABELS` (`NO_WIN_PROBABILITY` → «вероятность выигрыша равна нулю»). Never `Infinity`, `NaN`, `0` or blank.
- Effective win probability and fair odds in the table header carry the definitions via the how-to-read block, not tooltips.

### Exact score section anatomy

1. **Head row**: `h3` «Точный счёт»; chip «Без калибровки»; link «Как это считается» → `/methodology#extended-markets`.
2. **Deck**: «Вероятности 16 явных счетов от 0:0 до 3:3 и всех остальных исходов вместе. Семнадцать вероятностей в сумме дают 100%.»
3. `note-strip`: «Вероятности точного счёта — оценки модели без калибровки, а не гарантии.»

Caption: «В каждой клетке — вероятность счёта и справедливый десятичный коэффициент. Строки — голы хозяев, столбцы — голы гостей». Cell `min-width: 6.5rem`; below 640px the region scrolls horizontally with the row-header column `position: sticky` (inline-start 0, `--color-surface` background) so the home-goals label stays visible. No horizontal page scroll.
6. **OTHER row**: `<tfoot>` row — `th scope="row"` «Любой другой счёт», one `td colspan="4"` with the same two-line content. Fair odds unavailable (`ZERO_PROBABILITY` → «вероятность счёта равна нулю») renders «Недоступно» + reason in any cell.

No "most likely score" badge and no shading: emphasis would be colour-only or a new pattern, and it is not in D-10.

### Unavailable / legacy state (`SCORE_MATRIX_UNAVAILABLE`)

Both section headings stay mounted (stable anchors, predictable page structure, both removed from "success" semantics). Each section renders instead of its content one `<div class="state-notice tone-neutral" role="status" data-extended-state="UNAVAILABLE">` containing `state-chip state-chip--md tone-neutral` «Недоступно» + `state-dot`, then:

- the exact D-19 sentence: «Для этого прогноза расширенные рынки недоступны: матрица счёта не была сохранена.» (reason label from `EXTENDED_MARKETS_UNAVAILABLE_LABELS`);
- a second paragraph: «Три основных рынка этого прогноза (1X2, тотал 2.5, обе забьют) не затронуты.»;
- a link «Почему так — в методологии» → `/methodology#extended-markets`.

Neutral tone, `role="status"` (not `alert`): it is a permanent, expected property of legacy snapshots, not a failure. No retry control (retrying cannot change an immutable snapshot). No dismiss control. An unknown reason code or an unrecognised view shape fails closed to this same notice with the generic reason «Расширенные рынки для этого прогноза недоступны.» and never renders the AVAILABLE layout. Transport failure (`READ_FAILED`, distinct from UNAVAILABLE) renders `role="alert"` copy «Не удалось загрузить расширенные рынки. Остальные данные страницы не изменились. Повторите попытку.» with the existing «Повторить попытку» button when a client fetch exists (via `LocalDataBlock`); with the server-side fetch it offers a plain «Обновить страницу» link to the current URL.

## Odds-Entry Form Additions (D-20)

The «Ручная полная книга коэффициентов» panel keeps its structure (market select → draft restore notice → source label → odds fields → primary button → status line). Changes:

**Market select** (`#market`): five options in this order — «1X2», «Тотал 2.5», «Обе забьют», «Азиатский гандикап», «Точный счёт». Changing the family keeps the existing reset behaviour (clear selected odds snapshot and result).

**Asian handicap.** When «Азиатский гандикап» is chosen, a second field appears directly under the market select: `label` «Линия гандикапа (с позиции хозяев)» + native `<select id="ah-line">` with a placeholder option «Выберите линию» (value empty, **no auto-selected line** — consistent with the existing "newer data never replaces the user's choice" rule and protects book integrity) followed by the 21 lines ascending, each labelled «Хозяева −2.5 / Гости +2.5» … «Хозяева 0 / Гости 0» … «Хозяева +2.5 / Гости −2.5»; the option of the selected forecast's main line gets the suffix « (главная линия)». ## Accessibility and Keyboard Contract

ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ ПОЛЬЗОВАТЕЛЯ: пользовательский текст утверждённого контракта изменён по Pitfall 9 (14-RESEARCH.md).

Причина: при `retained-mass-v1` сетка делится на сохранённую массу, поэтому хвост за пределами 0–7 голов уже распределён пропорционально по всем клеткам матрицы. Строка «Любой другой счёт» равна `1 − сумма 16 явных счетов` и содержит перенормированные клетки с четырьмя и более голами, а не исходный хвост. Формулировка «хвост входит в строку «Любой другой счёт»» была неточной.

Две правки:

1. «Exact score section anatomy», пункт 4 (строка хвоста): было «Хвост матрицы вне 0–7 голов: {percent} — входит в строку «Любой другой счёт».», стало «Хвост матрицы вне 0–7 голов: {percent} — уже учтён нормировкой на сохранённую массу и распределён по всем счетам.» Чип «Хвост повышен» при `tail.warning` остаётся.
2. «Methodology and Model Card», пункт 4: фраза «строка «Любой другой счёт», в которую входит всё остальное, включая хвост матрицы за пределами сетки» заменена на «строка «Любой другой счёт» — все счета, не вошедшие в 16 явных, в том числе с четырьмя и более голами; хвост матрицы за пределами сетки 0–7 уже учтён нормировкой на сохранённую массу».
