# Phase 15 — UI Design Contract

> Visual and interaction contract for Phase 15 (7-Day Value Scanner). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Decisions D-01..D-13 of `15-CONTEXT.md` are binding. The user delegated every discretionary decision to Claude; each such decision is recorded below with its rationale (see "Decisions Recorded Here"). All user-facing text is Russian (AGENTS.md convention); identifiers, CSS classes and commit messages stay English. This spec is written in English like the other planning artifacts; every string in a "Copy" cell or in «guillemets» is the exact Russian text to ship.

**Scope.** One new read-only server-rendered page `/scanner` («Сканер value»): page header, persistent disclaimer, ordering/verbatim notices, match-grouped candidate list, the collapsible «Устаревшие коэффициенты» block, four page states (AVAILABLE, EMPTY, UNAVAILABLE, POLICY-UNMET info plaque), a navigation item and a home-page entry, new Russian labels, and the methodology `#limitations` sentence. **Out of scope:** filters, sorting controls, notifications, new value computations, any client-side JavaScript, charts, paper-trading actions (Phase 16), changing the value policy.

## Decisions Recorded Here (delegated by the user; defaults chosen)

| # | Decision | Rationale |
|---|----------|-----------|
| U-01 | **One DOM, a list of row blocks at every width — no `<table>` and no `ResponsiveEvidence`.** Each candidate is an `<li>` whose facts are a `<dl>` laid out with CSS grid (single column at 320 px, auto-fit columns wider). | (a) `ResponsiveEvidence` renders every value twice (table + cards), which doubles the HTML for up to 200 rows and breaks the byte-for-byte test (the stored string would occur twice per row); its mobile card hides all values inside «Полные доказательства», contradicting "edge and EV always visible". (b) A table with an aligned «Преимущество» column invites scanning the column by eye, which is exactly the leaderboard behaviour D-09 forbids. (c) The 14-09 lesson (min-content collapse of `th` under inherited `overflow-wrap: anywhere`, captions wider than the visible region, sticky headers needing z-index) is avoided by construction: there are no `th`, no caption and no sticky layer; labels (`dt`) are forced to `overflow-wrap: normal`, values (`dd`) to `anywhere`. |
| U-02 | Edge and EV carry the same visual weight in every row (20px/600), are never coloured, barred, badged or sized by magnitude. | No ranking by eye; same recipe as the Phase 14 "numbers in a table, never colour-coded" rule. |
| U-03 | Freshness is a text chip + the odds age line. FRESH = `tone-neutral`, AGING = `tone-warning`, STALE = `tone-warning` (inside the stale block). Never `tone-danger`, never `tone-positive`, never an opacity reduction. | «Приглушённая метка» (D-08) is satisfied by an amber, non-alarming chip; opacity would break contrast; `tone-positive` (green) would read as "good bet"; red reads as loss. State is always carried by chip text, not colour. |
| U-04 | Freshness level, age in seconds and the "forecast updated" flag come **from the API** (computed once against one `generatedAt` instant, named constants `scanner-freshness-v1` returned in the payload). The UI performs no time arithmetic beyond formatting an integer age. | Same "UI arithmetic prohibition" as Phase 14: one computation, deterministic tests, no client clock skew. D-06 leaves the owner of the computation open; this is the contract the page needs. |
| U-05 | Time zone is the constant `Europe/Warsaw` (D-09), stated once in the page header text. Kickoff: «сб, 28 ноября, 18:00». Odds captured: «25.11.2026, 14:05». Age: «7 ч назад». New pure helpers in `apps/web/components/time-format.ts` take the IANA zone explicitly and fall back to the raw input on invalid values (existing `formatInstant` contract). | `DataStateNotice` uses `DISPLAY_TIME_ZONE` (default UTC); the scanner is locked to Warsaw by D-09, so it must not silently follow the env default. Every instant also carries `<time dateTime="ISO">`. |
| U-06 | Receipt link target is the existing proxy `GET /internal-api/value/{receiptId}` (JSON, stored receipt), opened in a new tab. Each row `<li>` has a stable `id="receipt-{receiptId}"` for Phase 16 deep links. | A receipt page does not exist; the JSON proxy already serves the immutable receipt. A new tab keeps the user's place in a long list. |
| U-07 | The scanner never uses `formatOdds()`, `percent()` or `formatSignedPercent()` on receipt values. Edge, EV, model probability, no-vig probability, fair odds and quoted odds are rendered as the stored strings. | D-04. Note the match page shows the same numbers as percentages; the scanner says so in its "how to read" block, so the two pages do not look contradictory. |
| U-08 | All-stale case: if the main list has zero rows and the stale block has rows, the page is still AVAILABLE, the main list shows one neutral line, and the stale `<details>` is rendered `open`. | Otherwise a page with candidates would look empty. Server-rendered `open` needs no JS. |
| U-09 | Nav label is «Сканер», placed after «Анализ» and before «Результаты»; the `h1`, the page title and the home card stay «Сканер value». The fallback of this decision is applied: the long label overflowed at 768 px, so the nav label (only) was shortened; shortening alone was not enough, so between 768px and 1023px `.release-navigation nav a { padding-inline: var(--space-2) }` also applies. Accepted by the user on 2026-11-28. | Keeps the three "analysis" destinations adjacent and the seven entries on one row; avoids a new nav pattern; link height is unchanged. |

### Visual Direction

- A calm, chronological reference list, not a sportsbook board: hairline borders, `.panel` surfaces, no odds tickers, no ranking medals, no green/red win-loss framing, no urgency treatments, no countdowns.
- Grouped by match (the match is the unit the user thinks in); within a match the rows are plain separated blocks.
- The only emphasis is the pair edge/EV at 20px/600 — identical in every row, independent of value.

## Typography

New surfaces use exactly four sizes and two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / meta / `dt` / chip / sub-line / note / legend | 14px | 400 (chips 600) | 1.4 |
| Body / odds and probability values / links / notices / summary text | 16px | 400 (link and emphasis 600) | 1.55 (inherited body) |
| Match heading (`h3`), selection text, edge and EV values, count values | 20px | 600 | 1.2 |
| Section heading (`h2`) | 24px | 600 | 1.18 (inherited heading) |
The page `h1` keeps the inherited `.page-title` style; its size comes from the global `h1` rule shared by every page, so it is a page-level exception common to all pages, not a new size introduced by this phase. The 12px `--space-3` is likewise an inherited token accepted in 14-UI-SPEC.
The page `h1` keeps the inherited `.page-title` style (shared by every page; not a new size).

Rules:

- Weights are 400 and 600 only. State is never communicated by weight alone.
- All numeric values use `font-variant-numeric: tabular-nums`; edge/EV/count values use `--font-heading`.
- **Receipt values are never truncated, ellipsized, rounded or reformatted.** Stored strings can be long decimals (or exponent notation from `Decimal.toString()`); `dd` uses `overflow-wrap: anywhere` so a long value wraps mid-digit rather than overflowing; `dt` labels use `overflow-wrap: normal` so a label never breaks mid-word.
- Negative numbers are shown exactly as stored (ASCII `-`): the scanner does not substitute U+2212 into receipt values (byte-for-byte rule overrides the Phase 14 typographic convention). Line labels produced by `formatAhLine` («−0.75») remain as in Phase 14 because they are labels, not receipt values.

## State A — AVAILABLE

### Section header

`<section aria-labelledby="scanner-list-heading">` with `h2#scanner-list-heading` «Кандидаты value на ближайшие 7 суток» (24px/600) and a `.market-legend` line (14px):

«Кандидатов: {N}, матчей: {M}. Данные на {generatedAt, формат 25.11.2026, 14:05}.»

If the payload has `truncated: true`, directly under it a `<p class="note-strip">` containing a `state-chip state-chip--md tone-warning` chip «Показана часть списка» followed by the text: «Показаны кандидаты первых по времени матчей: {N} из {totalCandidates} (лимит списка — {limit}). Более поздние матчи в список не вошли.» ({N} is the number of items; {totalCandidates} and {limit} are interpolated from the payload).

If the main list has zero rows (U-08): `<p>` «Кандидатов со свежими или стареющими коэффициентами нет. Все кандидаты — в блоке «Устаревшие коэффициенты» ниже.»

### Match group

Outer `<ol class="scanner-groups">` (ordered: chronological). Each item is `<li class="panel scanner-match">`:

1. **Match head** `<div class="scanner-match-head">`:
   - `<h3>` containing `<a href="/fixtures/{fixtureId}">{homeTeam} — {awayTeam}</a>` (20px/600; the link text is the whole match name; wraps at word boundaries, `overflow-wrap: break-word`; the link is a standalone target at least 44 px high);
   - `<p class="scanner-match-meta">` (14px muted): `{competition}` (the stored `League.name`; the data model has no separate competition table) · `<time dateTime="{kickoffAt ISO}">{kickoff}</time>` — e.g. «Премьер-лига · сб, 28 ноября, 18:00». Separator is a visible « · » inside the text, not a pseudo-element.
2. **Rows** `<ul class="scanner-rows">`, each `<li class="scanner-row" id="receipt-{receiptId}" data-freshness="FRESH|AGING">` (the stale block uses `data-freshness="STALE"`).

Match groups preserve the API order exactly (kickoff ascending, then rows in market order 1X2 → тотал 2.5 → обе забьют → АГ → точный счёт, then selection). **The view never sorts or re-groups by anything.** There is no sort control, no `aria-sort`, no «по возрастанию/убыванию» wording.

DOM order (= reading order = tab order):

| # | Block | Markup | Content |

| 2 | Facts | `dl.scanner-facts` | four `div` groups in this order (below) |
| 3 | Forecast-updated note (conditional) | `p.scanner-note` | only when `forecastNewerAvailable`: «После этой квитанции вышел более новый снимок прогноза. Значения в строке относятся к прежнему снимку.» |

**Facts (`dl.scanner-facts`, four groups, equal columns):**

| `dt` (14px muted) | `dd` (value) | Sub-line (`.market-sub`) |
|-------------------|--------------|--------------------------|
| «Преимущество (edge)» | stored `edge` string, 20px/600 heading font | «доля вероятности, как в квитанции» |
| «Ожидаемое value» | stored `expectedValue` string, 20px/600 heading font | «на 1 единицу ставки» |
| «Коэффициент букмекера» | stored decimal odds string, 16px/400 | «Источник: {source}» then «Введены {captured}, {age}» (see below) |
| «Вероятность модели» (AH: «Эффективная вероятность выигрыша») | stored `modelProbability` string, 16px/400 | «доля, как в квитанции» |

The payload also carries `oddsCapturedAt` as informational data; the UI does not render it and freshness never uses it.

- Source/time sub-lines: `<span class="market-sub">Источник: {source}</span>` and `<span class="market-sub">Введены <time dateTime="{submittedAt ISO}">{25.11.2026, 14:05}</time>, {7 ч назад}</span>`. `source` is user-entered manual text: render as plain text only (React escapes), `overflow-wrap: anywhere`, no truncation, no markup interpretation. ## Accessibility and Keyboard Contract

- One `h1`; headings never skip levels (`h1 → h2 → h3`). Rows have no headings. Match groups are an ordered list (`ol`) of `li`s; rows are a `ul` inside each match `li`; the list structure gives screen readers "list of N items" for free.
- Native `details`/`summary` everywhere (stale block, row details, how-to-read): Enter/Space toggles, the browser exposes expanded state; no custom `aria-expanded`. `summary` keeps the global focus ring and a 44px target (stale block summary explicitly).

- Every status is text: freshness chips, «Прогноз обновлён», «Пусто», «Недоступно». Nothing relies on colour; forced-colors keeps chip borders and panel borders.
- Link names are unique and descriptive via `.sr-only` suffixes (above). The match `h3` link text is the match name.
- `<time dateTime="…">` for kickoff, odds capture time and `generatedAt`; zone stated in the scope line.
- Russian `lang` is the page default; `code` (ids, version ids) and stored decimal strings are exempt.
- Targets ≥ 44px for all standalone links (the match heading link included), buttons and `summary`; inline links inside sentences (`Методология и ограничения` inside the plaque) are exempt as inline text but keep the global focus ring.
- 200% zoom and 320px: no horizontal page scroll, no clipped values, no lost link.
- No auto-moving focus, no timers, no hover-only information.
