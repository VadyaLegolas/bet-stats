# Proxy WebSocket upgrades in the operator gateway

## Problem (locked diagnosis — do not re-investigate)

In the standard dev topology (`next dev` on :3000 behind the operator gateway on
:8080), `http://127.0.0.1:8080/internal/operations` renders SSR HTML but React
never hydrates (no `__react*` keys, refresh button stays disabled, `useEffect`
`load()` never fires). Direct :3000 hydrates fine; HTML through the gateway is
byte-identical.

Root cause: Next 16.3.3 dev builds `createFromReadableStream` with an active
`debugChannel` (`__NEXT_DEV_SERVER` + `__NEXT_REACT_DEBUG_CHANNEL`), so the
response closes only after BOTH streams finish — the second being the readable
fed by `ws://<origin>/_next/hmr?id=<self.__next_r>`. `infra/operator-gateway/server.mjs`
has no `'upgrade'` handler, so the browser's WS handshake against :8080 gets a
Node-default `404`, the debug-channel readable never closes, and hydration hangs
silently. Production (`next start`) has no debug channel, so the existing e2e
(`tests/e2e/operations-gateway.spec.ts`) does not cover this dev path. UAT-6 of
phase 08 requires `/internal/operations` through the gateway on the standard dev
topology (`scripts/app-lifecycle.ps1`) — a real product bug.

## Change (locked design)

Add a `server.on("upgrade", ...)` handler to `infra/operator-gateway/server.mjs`
alongside the existing request handler, reusing the existing helpers:

1. **Fail-closed target:** `requestTarget(incoming.url, config.webOrigin)` —
   `undefined` → raw `HTTP/1.1 400` on the socket, no upstream connection (same
   SSRF guarantee as the HTTP path).
2. **Same auth gate:** `isProtectedPath(target.pathname)` +
   `authenticateBasic(incoming.headers.authorization, ...)` — failure → raw
   `HTTP/1.1 401` with the exact `www-authenticate` realm used by
   `unauthorized()` (`Bet Stats Operator`), socket ended, zero upstream
   attempts. No HMAC signing on this path (locked: no HTTP route consumes it).
3. **Header forwarding:** copy `incoming.headers` minus `host`, `authorization`,
   and the spoofable `x-operator-*` operator headers. KEEP `connection`,
   `upgrade`, and every `sec-websocket-*` header — they are required for the
   handshake, so the HTTP path's `forwardHeaders` (which strips hop-by-hop by
   design) must NOT be reused as-is here.
4. **Upstream handshake** via `httpRequest(target, { method: "GET", headers })`
   (HTTPS branch mirrors the HTTP path), explicitly ended since there is no
   body:
   - `'upgrade'` → relay the 101 status line + raw upstream headers verbatim to
     the client socket, forward `head`/`upstreamHead` bytes, then bidirectional
     `pipe` (client socket ↔ upstream socket); clear the handshake timer;
     socket errors destroy the peer.
   - `'response'` → the upstream refused (e.g. Next 404): relay status line +
     headers + piped body raw to the client socket, then end it — fail closed,
     never a partial 101.
   - handshake timeout ~`upstreamTimeoutMs` (10s) destroying both sockets;
     `'error'` → destroy the client socket.
   - After a successful upgrade no request timeouts apply to the pipe
     (verified: Node detaches upgraded sockets from `requestTimeout`/
     `headersTimeout`); the multi-second echo test in Task 2 guards this.
5. **Out of scope (locked):** no signing additions, no changes to
   `forwardHeaders`/`security.mjs` semantics for ordinary requests.

## Threat model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → gateway :8080 (upgrade) | Untrusted client sends a raw WS handshake that must pass target + auth gates before any upstream socket is opened |
| gateway → Next :3000 (upgrade) | Upstream response bytes are relayed verbatim onto the client socket |

### STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-mv2-01 | Tampering (SSRF) | upgrade target resolution in `server.mjs` | high | mitigate | `requestTarget()` fail-closed reuse; invalid-target test asserts a raw 400/destroy and zero upstream requests |
| T-mv2-02 | Spoofing | protected-path upgrade auth | high | mitigate | `authenticateBasic` gate before any upstream connect; raw 401 with the HTTP path's realm; test asserts zero upstream upgrade attempts |
| T-mv2-03 | Information disclosure | upgrade header forwarding | medium | mitigate | new header helper strips `host`, `authorization`, and `x-operator-*` while keeping only handshake-required headers |
| T-mv2-04 | Denial of service | stalled upgrade handshake | low | mitigate | 10s handshake timer destroys both sockets on timeout/error |
| T-mv2-SC | Tampering | npm/pip/cargo installs | high | mitigate | no package installs in this task |
