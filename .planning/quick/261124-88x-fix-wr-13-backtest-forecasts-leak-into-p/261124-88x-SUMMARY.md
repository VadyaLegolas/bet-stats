# Quick Task 261124-88x: WR-13 backtest forecasts leak into the public scorecard pool

**One-liner:** `ForecastSnapshot.origin` (PRODUCTION | BACKTEST, forward-only migration, guarded as immutable) written from the orchestrator initiator, every public reader and the Dixon-Coles rho fit restricted to PRODUCTION, proven on real PostgreSQL by five mutation checks.

## What was fixed, per decision

- **D-01 migration, schema, client.** `enum ForecastOrigin`, column `ForecastSnapshot.origin NOT NULL DEFAULT 'PRODUCTION'` (`20261124_phase11_forecast_snapshot_origin`, forward-only, header documents the rollback limit). Existing rows are not touched (constant default, metadata-only on PostgreSQL 18). `guard_forecast_snapshot()` is an exact copy of the previous body with `origin` appended to both `ROW(...)` lists. The generated Prisma client was regenerated and committed; only the 6 files for ForecastSnapshot/ForecastOrigin changed (no line-ending or version noise).
- **D-02 write path and collisions.** `forecastOriginOf(initiator)` in the orchestrator, `publish(draft, { origin })` (optional second parameter, one-argument doubles stay valid), `origin` written on create. The identity has no origin: a collision returns the existing snapshot unchanged whichever origin it has. The revision chain stays shared per `(fixtureId, kind)`.
- **D-03 readers.** `origin: "PRODUCTION"` added to `findIssued`, `listIssued`, scorecard `load`, `enumerateAvailableCohorts`, `listValueCandidates`, the fixture list enrichment, comparison `findExact`, value `findForecast` (both became `findFirst`) and the sweep issued-kinds lookup.
- **D-04 rho decision (required by the user): BACKTEST is excluded from the fit.** Evidence: every backtest fit uses `asOf = window.trainingEndsAt`, so WR-04's `issuedAt <= asOf` already drops later-written backtest snapshots; excluding them changes nothing for backtests or the comparison receipt (e2e stays green). A production forecast fits at `asOf` near now and previously read backtest snapshots, so an operator comparison could silently move rho of later live forecasts and feed the model that the same scorecard then scores. Counter-argument recorded, not adopted: backtest rows could bootstrap rho on a young database; that must be an explicit labelled option (deferred-items.md #2). Test: a league with 200 BACKTEST snapshots gets `sampleSize 0` and the same rho as the pooled-only reference. Residual: legacy backtest rows written before the migration are PRODUCTION and stay in the fit.
- **D-05 tests.** (a) e2e step 7: after a model-comparison run on a database with no production forecast, public `loadCohort` (modelVersion all/each, market ONE_X_TWO/all) is 0/0/0/0, `enumerateAvailableCohorts` and value candidates are empty, 64 BACKTEST snapshots, 0 PRODUCTION, 192 backtest scores still present. (b) `forecast-origin` test 1: a V1 backtest on an existing production identity leaves the snapshot PRODUCTION, public, and counted (fixture 1, forecast 1, events 3).
- **D-06 documents.** `11-REVIEW.md` (WR-04 residual closed, WR-13 fixed), `11-REVIEW-FIX.md` (WR-13 moved to Fixed Issues, frontmatter `fixed: 8`, `skipped: 0`, `all_fixed`, verification table), `11-OPERATOR-COMPARISON.md` (origin, legacy rows, migrate and rebuild), new `deferred-items.md` (`valueByFixture` and 6 more items).
- **D-07.** SQLSTATE 40001 not touched; it did not appear in `settlement-multi-forecast` (15/15, single run).
