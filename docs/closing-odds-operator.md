# Запись коэффициентов закрытия: инструкция оператору

Документ для оператора, который записывает закрывающие коэффициенты (CLV-01). Эти данные нужны только для оценки: по ним на странице «Ведомость результатов прогнозов» считается CLV без маржи (`no-vig-clv-v1`). CLV не прогноз, не обещание прибыли и не влияет на отбор и порядок кандидатов value.

## Когда записывать закрытие

- Запись возможна только **до начала матча** и **до расчёта матча**. Поздние записи отклоняются и не сохраняются с пометкой: так закрытие нельзя подогнать под результат.
- Записывайте последний набор коэффициентов перед началом матча. Момент наблюдения (`observedAt`) должен быть строго до начала матча и не в будущем относительно часов сервера.
- Один запрос записывает **полный набор выборов одного рынка** одного матча в один момент. Поддерживаются пять семейств рынков: `ONE_X_TWO` — 3 выбора (`HOME`, `DRAW`, `AWAY`), `OVER_UNDER_2_5` — 2 (`OVER_2_5`, `UNDER_2_5`), `BTTS` — 2 (`YES`, `NO`), `EXACT_SCORE` — 17 выборов (счета от `0-0` до `3-3` и `OTHER`) и `ASIAN_HANDICAP:<линия>` — 2 выбора (`HOME`, `AWAY`) на одну линию. Неполный набор отклоняется, потому что без полного набора нельзя убрать маржу.
- Линия азиатского гандикапа задаётся с позиции хозяев в каноническом виде: от `-2.5` до `+2.5` шагом `0.25` (например `ASIAN_HANDICAP:-0.75`, `ASIAN_HANDICAP:0`, `ASIAN_HANDICAP:+1.25`). **Набор по гандикапу записывается отдельно для каждой линии**: закрытие линии `-0.75` не заменяет и не подменяет линию `-1`; при оценке CLV значение берётся только из набора той же линии. Запись вида `+1.00`, `0.0` или линия вне списка отклоняется как `UNSUPPORTED_MARKET`.
- Источник (`sourceConvention`) должен **в точности совпадать** с источником ручных коэффициентов кандидата. По другому источнику значение CLV не считается: на странице будет причина «закрытие записано по другому источнику, чем коэффициент кандидата».

## Как записывать

Данные записываются через API или командную строку. Браузерной формы нет намеренно: подписанный прокси веб-приложения не передаёт тело запроса (путь без JSON, как у операторских операций), а менять прокси ради этой формы вне объёма фазы. Форма отложена.

### Через API

`POST /internal/closing-odds` с заголовком `x-operator-credential`. Без верного заголовка маршрут отвечает 404 (не отличает отсутствующий и неверный пароль).

```bash
curl -sS -X POST "$API_ORIGIN/internal/closing-odds" \
  -H "content-type: application/json" \
  -H "x-operator-credential: $OPERATOR_CREDENTIAL" \
  -d '{
    "fixtureId": "ИДЕНТИФИКАТОР_МАТЧА",
    "market": "ONE_X_TWO",
    "sourceConvention": "МЕТКА_ИСТОЧНИКА",
    "observedAt": "2026-11-30T11:00:00.000Z",
    "selections": [
      { "selection": "HOME", "decimalOdds": "2.10" },
      { "selection": "DRAW", "decimalOdds": "3.40" },
      { "selection": "AWAY", "decimalOdds": "3.60" }
    ]
  }'
```

В теле допустимы только перечисленные ключи; вид наблюдения и формат коэффициентов задаёт сервер (закрытие рынка, десятичные коэффициенты). Идентификатор матча тот же, что в адресе страницы матча (`/fixtures/<идентификатор>`).

Новые рынки записываются тем же маршрутом, меняются только `market` и `selections`. Азиатский гандикап, одна линия:

```json
{
  "fixtureId": "ИДЕНТИФИКАТОР_МАТЧА",
  "market": "ASIAN_HANDICAP:-0.75",
  "sourceConvention": "МЕТКА_ИСТОЧНИКА",
  "observedAt": "2026-11-30T11:00:00.000Z",
  "selections": [
    { "selection": "HOME", "decimalOdds": "1.90" },
    { "selection": "AWAY", "decimalOdds": "1.95" }
  ]
}
```

Точный счёт: `"market": "EXACT_SCORE"` и все 17 выборов — `0-0`, `0-1`, …, `3-3` (шестнадцать счетов) и `OTHER` — по одному разу. Пропуск любого выбора даёт `INCOMPLETE_MARKET_SET`.

### Через командную строку

Нужны собранный проект (`pnpm build`) и переменная `DATABASE_URL`.

```bash
node scripts/closing-odds.mjs record \
  --fixture ИДЕНТИФИКАТОР_МАТЧА --market ONE_X_TWO --source МЕТКА_ИСТОЧНИКА \
  --observed-at 2026-11-30T11:00:00.000Z --odds HOME=2.10,DRAW=3.40,AWAY=3.60
```

Новые рынки в командной строке:

```bash
# азиатский гандикап: одна линия за запись
node scripts/closing-odds.mjs record \
  --fixture ИДЕНТИФИКАТОР_МАТЧА --market ASIAN_HANDICAP:-0.75 --source МЕТКА_ИСТОЧНИКА \
  --observed-at 2026-11-30T11:00:00.000Z --odds HOME=1.90,AWAY=1.95

# точный счёт: все 17 выборов (16 счетов от 0-0 до 3-3 и OTHER)
node scripts/closing-odds.mjs record \
  --fixture ИДЕНТИФИКАТОР_МАТЧА --market EXACT_SCORE --source МЕТКА_ИСТОЧНИКА \
  --observed-at 2026-11-30T11:00:00.000Z --odds 0-0=9.5,0-1=12,0-2=26,0-3=70,1-0=7,1-1=6.5,1-2=13,1-3=40,2-0=9,2-1=9.5,2-2=19,2-3=60,3-0=18,3-1=20,3-2=40,3-3=100,OTHER=30
```

Справка: `node scripts/closing-odds.mjs --help`. Код выхода: 0 — записано или уже было записано, 1 — отказ или конфликт, 2 — ошибка в параметрах.

## Ответы и коды отказов

| Ответ | Смысл |
|-------|-------|
| 201 | Набор записан целиком (одна транзакция). |
| 200 | Тот же набор уже записан: повтор безопасен, новых строк нет. |
| 400 | Тело запроса неверной формы (лишние ключи, не объект). |
| 404 | Нет или неверен `x-operator-credential`. |
| 409 `CLOSING_OBSERVATION_CONFLICT` | Для этого матча, рынка, источника и момента уже записан другой коэффициент. |
| 422 | Запрос отклонён по правилам; код в теле ответа (ниже). |

| Код | Что сделать |
|-----|-------------|
| `INCOMPLETE_MARKET_SET` | Передайте все выборы рынка, ровно по одному разу. |
| `DUPLICATE_SELECTION` | Уберите повторяющийся выбор. |
| `UNSUPPORTED_MARKET` | Допустимы `ONE_X_TWO`, `OVER_UNDER_2_5`, `BTTS`, `EXACT_SCORE` и `ASIAN_HANDICAP:<линия>` с линией от `-2.5` до `+2.5` шагом `0.25`. |
| `INVALID_OBSERVED_AT` | Формат UTC с миллисекундами: `2026-11-30T11:00:00.000Z`. |
| `OBSERVED_AT_NOT_PRE_KICKOFF` | Момент наблюдения должен быть строго до начала матча. |
| `OBSERVED_AT_IN_FUTURE` | Момент наблюдения не может быть позже часов сервера. |
| `RECORDED_AFTER_KICKOFF` | Матч уже начался: запись закрыта, исправить нельзя. |
| `FIXTURE_ALREADY_SETTLED` | По матчу уже есть расчётная квитанция: запись закрыта. |
| `INVALID_ODDS` | Коэффициент — десятичное число строго больше 1. |
| `INVALID_SOURCE_CONVENTION` | Источник не указан. |
| `FIXTURE_NOT_FOUND` | Матч с таким идентификатором не найден. |
| `UNKNOWN_SOURCE_CONVENTION` | Источник не совпадает ни с одним источником ручных коэффициентов. |
| `CLOSING_OBSERVATION_CONFLICT` | См. выше: исправление записывайте новым, более поздним `observedAt`. |

## Исправление ошибки

Записи нельзя изменить или удалить (append-only, защита на уровне базы). Исправление — **новое наблюдение с более поздним `observedAt`** до начала матча: побеждает последнее до начала матча. Если матч уже начался или рассчитан, исправить закрытие нельзя.

## Что увидит пользователь

На странице «Ведомость результатов прогнозов», в реестре кандидатов, колонка «CLV без маржи» показывает значение, версию политики, время и источник закрытия. Если закрытия нет или оно непригодно, показывается причина по-русски; значение не достраивается и не интерполируется.

## Честные ограничения

- Закрытие вводится вручную из одного источника и не является консенсусом рынка; ошибка ввода меняет значение.
- Выборки малы: значение по одному кандидату шумное.
- CLV не заменяет вероятностные меры качества (Brier, Log Loss, надёжность).
- Для азиатского гандикапа и точного счёта CLV остаётся тем же слоем оценки: он не влияет на отбор кандидатов и не меняет их порядок. Правила записи (оператор, только до начала матча, append-only) для новых рынков те же, что для остальных.
